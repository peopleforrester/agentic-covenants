# Inventory

Per-cell discovery guidance and reference tooling for the [Agentic Inventory Matrix](../framework/INVENTORY_MATRIX.md). Hybrid: documentation discipline (operator-declared) plus reference code (self-declared registration daemon, discovered tooling).

## Layout

```
inventory/
├── identity/{self-declared,operator-declared,discovered}/
├── authorization/{self-declared,operator-declared,discovered}/
├── blast-radius/{self-declared,operator-declared,discovered}/
├── approval-gating/{self-declared,operator-declared,discovered}/
├── supply-chain/{self-declared,operator-declared,discovered}/
└── templates/
    └── inventory-record.yaml
```

The structure is the same five concerns as the operational and Charter matrices, but with three different layers: **self-declared** (the agent reports itself), **operator-declared** (a human registry), and **discovered** (passive observation).

## Cross-layer mismatch as a signal

The principle that defines this matrix:

| Cross-layer state | What it means | Action |
|---|---|---|
| All three populated, agree | Defensible inventory | Continue |
| Discovered ∧ ¬operator-declared | **Shadow agent** | Investigate ownership; charter or retire |
| Operator-declared ∧ ¬discovered | **Ghost agent** | Retired-but-not-removed, or failing-to-start |
| Self-declared ∧ ¬operator-declared | Charter integrity failure | Audit |
| Self-declared deps ≠ operator-declared deps | Scope or dependency drift | Re-review charter |

Build alerting against these mismatches.

## Cell README structure

Every cell directory has a README following the format:

1. **What this cell records.** The specific data this layer captures for this concern.
2. **Reference tooling.** Sample registration daemon, sample discovery script, sample registry YAML, whichever applies to the layer.
3. **Cross-layer cross-references.** Which other cells should agree with this one, and how to surface mismatches.
4. **Common failure modes.**
5. **Citation.**

## Templates

[`templates/inventory-record.yaml`](./templates/inventory-record.yaml) is the canonical record per agent. Generated by joining the outputs of the three layers. The self-declared layer pushes registration over the wire; the operator-declared layer is committed YAML in source control; the discovered layer is tooling output joined to the other two.

## Inventory powers the rest

- Charter: Inventory enables retirement-criteria enforcement against running state.
- Covenants: Inventory enables per-agent control selection based on declared risk tier.
- Sentinels: Inventory provides the baseline; drift becomes an alert.
- Interventions: Inventory provides the credential / namespace / runtime mapping each runbook needs.
- Restorations: Inventory is the last-known-good state Restorations rebuilds toward.
